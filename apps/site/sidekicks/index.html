02 When it wakes

On a schedule, on a signal, or on request.

Triggers decide when a Sidekick starts by itself. Without one, it waits to be asked.

Schedule

Every morning at 7.

Hourly, daily, weekly or any interval, in your time zone.

Event

When something happens.

A new email, a merged pull request, a meeting note. Add a written condition to narrow it down.

Webhook and email

From anywhere else.

Point any system at a Sidekick’s inbound webhook, or forward it an email.

03 Access

It asks for facts. Never for permission.

“Needs input” means a Sidekick is missing something only a person knows. It never means it is waiting to be allowed to use a tool: the access it runs with was chosen when someone set it up.

  1. 01

    Delegated access

    A Sidekick runs with access someone chose to give it, and each run says whose it used.

  2. 02

    Shared on purpose

    Keep a Sidekick to yourself, share it with named people, or open it to the organization.

  3. 03

    Changed in conversation

    Managers change a Sidekick by talking to its drafting assistant, right in its conversation.

  4. 04

    Pause any time

    One switch stops it waking up until you turn it back on.
