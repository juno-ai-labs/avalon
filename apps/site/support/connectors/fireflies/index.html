Fireflies.

Your own Fireflies meetings through its live tools, or the team's transcripts and summaries through an admin API key. Either can be connected first.

Connect for me

In Rally Settings → Connections → Fireflies, choose Connect for me and complete Fireflies' browser sign-in. Your work streams then gain the tools Fireflies' own MCP server publishes, against your Fireflies account and nobody else's.

That catalogue is Fireflies', not Rally's, and it includes actions that change and share meetings. Every call is recorded before it runs, and these tools are excluded from sub-agent runs. Rally does not ask you to confirm individual tool calls.

Fireflies' sign-in grants Rally the profile and email scopes it publishes and nothing more. If Fireflies issues no long-lived refresh, your connection asks you to sign in again when its access expires; Settings shows it as needing reconnection.

Connect for workspace

A Rally workspace administrator chooses Connect for workspace and pastes an API key from Fireflies → Integrations → Fireflies API. Enter it only in the password field in Settings. Rally checks the key with Fireflies before storing anything: a rejected key leaves no connection behind.

Every work stream in the workspace can then search meetings, read a meeting's AI summary, and read its transcript. These three tools are read-only — they never share, retitle, move, or delete a meeting.

What the key can see is the connected Fireflies account's own access. Team-wide visibility additionally requires Fireflies Enterprise with Super Admin enabled. Fireflies publishes no way to check which of the two applies, so Rally does not guess: if searches come back empty for other people's calls, the key sees only its own account's meetings. Everyone in the Rally workspace can read whatever it does see.

Finish the webhook in Fireflies

Fireflies offers no API for registering a webhook, so this step is yours and Rally cannot do it or check it. After the key is accepted, Rally shows the endpoint URL and a signing secret once. Copy both, then in Fireflies:

  1. 1

    Open the Webhooks V2 configuration page ↗.

  2. 2

    Paste Rally's endpoint URL into Webhook URL and Rally's signing secret into Signing Secret.

  3. 3

    Subscribe meeting.transcribed and meeting.summarized. Leave meeting.bot_joined unselected — Rally rejects it.

  4. 4

    Save.

Fireflies holds one webhook URL per account, so this replaces any URL already configured there. The signing secret is required on Rally's side: unsigned deliveries are rejected, so skipping it means no meetings arrive at all.

Until this is done the installation reads Needs attention and no meetings reach Rally. It changes to Connected on the first delivery Rally can verify — there is no test ping, so the next meeting the account records is the test. Fireflies fires these webhooks only for meetings the connected account organizes.

A finished meeting then arrives as workspace activity within a couple of minutes, and automations can act on it.

Check and recover

Personal authorization and workspace delivery have separate status. Refresh your personal connection to sign in again. For the workspace connection, open Manage events to see connection status and the last meeting received; Test checks the API key. Use Get help if a problem continues.

If Fireflies stops accepting the key, the connection is marked as needing reconnection. Under Advanced, Replace workspace API key swaps it without changing the endpoint URL, the signing secret, or anything you configured in Fireflies.

To replace the signing secret, remove the connection, delete the webhook in Fireflies, and connect again. Meetings recorded in between do not arrive.

Removing the connection stops Rally reading and receiving immediately. Rally cannot delete the webhook from Fireflies for you: delete it there, or leave it — deliveries to a removed connection are rejected.

If meetings stop arriving, check the last received time and that the Webhooks V2 page still points at Rally's URL with both events subscribed. Fireflies does not retry a failed delivery.

For support, share the connection ID, region, error, and affected time. Never share API keys, signing secrets, OAuth tokens, or meeting content.
