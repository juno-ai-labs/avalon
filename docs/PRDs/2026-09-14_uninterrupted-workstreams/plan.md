# Implementation plan

Implement the full PRD on `codex/uninterrupted-workstreams`, rebased onto the merged PRD and current main. This is an implementation change after PR #764; the feature is complete only when the full acceptance flow works.

## Work sequence

1. Carry advisory `longRunning` tool metadata through discovery and activation, initially for image generation/editing. Verify the provider-visible hint without changing dispatch, timeouts, or authorization.
2. Complete the wire contract and runtime schemas, including the approved optional attachments and refusal to restart archived work. Agent addresses must identify the whole conversation, including Sidekick authoring substream `0`.
3. Add durable implicit teams, additive membership, minimal ownership lineage, and accepted message/reply references using the existing regional object authorities. Reuse existing durable delivery and recovery; do not introduce task entities or semantic acknowledgements.
4. Create hidden background substreams and start their ordinary harness independently. Inherit the parent model and delegated authority, pass only explicit opening context, retain independent plugin discovery, and support recursive delegation.
5. Install start/list/send/reply/stop tools. Deliver messages at safe execution boundaries, wake idle agents, return results through their originating exchange, and cascade stops only through owned descendants. Archive must stop owned work and prevent message-triggered resurrection.
6. Add Sidekick discovery and minimal creation, preferring reuse in the current workstream and defaulting new ownership to that workstream. First authorized contact adds the independently owned authoring agent to the team; drafting tools live only there.
7. Keep participant messages available during background work. Render only a pluralized running-agent count, including nested workers, without inspection or direct chat. Preserve foreground-only stop and remove the participant queue/steer choice from ordinary conversation.
8. Remove the replaced inline subagent/task paths, document direct operational cutover, update subsystem owners and acceptance documentation, and verify the feature end to end.

## Decisions for the final review

The user asked that decisions be collected until the end of implementation rather than interrupting work while they are away. Preserve the approved product behavior and make reversible implementation choices. Record material additions here before final review.

The user explicitly confirmed that Bind must remain the core loop owner and that changes to Bind itself are preferable to workarounds. The initial audit found that the proposed instruction to finish without response text conflicts with the production harness's `acceptEmptyCompletion: false`. Do not enable empty completions or weaken defect checks to make that instruction work. Resolve deliberate completion without a reply through supported Bind behavior, and record any model-tool contract addition here for final approval. Also verify the background stop timestamp remains only durable admission state: active model/tool settlement must continue through the existing fenced stop path.

Proposed contract addition for approval: `end_turn({})` explicitly ends the current turn without an automatic teammate reply. Bind 15 already provides the native tool-ended completion outcome, so this needs no runtime fork, weakened empty-completion policy, or parallel loop. Rally persists the outcome in its existing host receipt and retains it during recovery. Real workerd coverage exercises plugin loading, tool-ended completion with leading text, absence of an automatic reply, and later continuation. Removing reply suppression caused an unwanted foreground run; removing the receipt flag caused durable-outcome verification to fail. Both mutations were restored.

Archive settlement adjustment for final review: liveness renewal no longer reauthorizes an already-started step during streaming or final settlement. The existing authority checks remain before each new model call and each tool call. The active-archive test exposed the old callback turning archive into `run_state_persistence_failed`, preventing Bind from reaching its recorded stop. With those responsibilities separated, the real worker settles as cancelled, an independently owned workspace Sidekick completes, and its result delivery settles without restarting the archived workstream. No Bind stop or receipt transition is bypassed.
