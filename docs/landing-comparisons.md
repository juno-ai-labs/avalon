# Landing comparisons and site footer

The public site's "Compared to" pages and the column footer they share with the
landing page and the Trust Center. The landing page's "Compared to" section lists five rival
products in one table, and each rival has its own page at `/compare/<slug>/`
that answers "Rally vs X" for a person or an AI search engine. There is no
`/compare/` index page: `_redirects` sends it to `/#compare`. The footer lists every comparison in one column and
every Trust Center page in another.

The copy is written by the Rally team and says so on every page. It is meant to
be biased toward Rally but not wrong about anyone else, so every claim about a
rival should be checkable on that rival's public pages as of the date the page
carries.

## Where the code lives

| Path | Responsibility |
| --- | --- |
| `apps/site/content/compare/<slug>.md` | One rival's page as GitHub-flavored Markdown: front matter plus fixed `##` sections. The only place its copy lives. |
| `apps/site/src/comparison-pages.ts` | Reads and validates the Markdown (`loadComparisons`, `parseComparison`) and renders one page's HTML (`renderComparisonPage`). |
| `apps/site/src/social-cards.ts` | Draws 1200x630 unfurl cards: `renderSocialCard` for any page, `renderComparisonCard` for a rival. |
| `apps/site/src/site-chrome.ts` | `comparisons` (the loaded list), `trustPages`, and the renderers for the footer and the comparison table. |
| `apps/site/vite.config.ts` | `rally-site-chrome` swaps markers for markup; `rally-markdown-pages` turns each Markdown file into `/compare/<slug>/` and its `social.png`, in the build and the dev server. |
| `apps/site/src/landing.css` | Footer, table, and comparison page styles, in the landing page's tokens. |
| `apps/site/public/robots.txt` | Lists `/compare/sitemap.xml` beside the main `/sitemap.xml`; both comparison sitemap and `/llms.txt` are generated by the build. |

## How it works

### Pages from Markdown

Each rival is one Markdown file whose front matter holds `slug`, `name`,
`maker`, `order`, `title`, `description`, `updated`, `kind` and `edge`, and
whose body is a short answer followed by `## Side by side` and
`## Where Rally wins`. The file reads as an ordinary document on
GitHub, so editing copy needs no HTML.

`vite.config.ts` registers `compare/<slug>/index.html` as a build input for each
file, though no such file exists. The plugin's `resolveId` and `load` hooks
answer for those paths with `renderComparisonPage`, and Vite then treats the
result like any other HTML entry: scripts are bundled, `transformIndexHtml`
runs, and the page lands at `dist/compare/<slug>/index.html`. In development a
middleware renders the same HTML for `/compare/<slug>/`. Every other file the
comparisons produce (each card, each `index.md`, `/compare/sitemap.xml` and
`/llms.txt`) sits in one `generatedFiles` map in `vite.config.ts`: the build
emits each entry and the dev server answers for the same paths. The build also publishes
the file itself at `/compare/<slug>/index.md`, linked from the page as
`rel="alternate" type="text/markdown"` and from `llms.txt`, so an agent can read
the page without parsing HTML.

`renderComparisonPage` lexes the body with `marked` and maps each `##` section
to the landing page's layout: the table becomes `versus-table` with
`data-label`s for the phone layout, `###` items become `points` cards, and a
blockquote there becomes the dad-joke aside. A blockquote in the short answer
renders in place as a plain quote, and anything after the table (a quote, a
paragraph, a list) renders in place below it.
An unknown `##` heading, a missing required section, or a missing front matter
field throws, so the build fails instead of shipping a broken page.

### Shared footer and table

A page that wants shared markup holds a marker comment. `<!-- rally:site-nav -->`
becomes the header's links and download button, `<!-- rally:site-footer -->`
becomes the column footer and `<!-- rally:comparison-table -->` becomes the
table of rivals, so no page lists rivals or header links by hand. The nav's
section links point at `/#features` and friends, so the same markup works on
the landing page and on every other page. Markers work anywhere in the
file, attribute values and JSON included. The plugin runs with `order: 'pre'`, before the access-copy
and telemetry plugins. An unknown marker throws. Both read `comparisons`,
which is sorted by each file's `order`.

### Social cards

Every rival page sets `og:image` and `twitter:image` to
`/compare/<slug>/social.png`. The build
draws each card in `generateBundle` from the page's own `name` and `edge`, so a
card can never disagree with its page. The card is the landing hero image under
a dark gradient, with the Rally mark, a "Compared to" eyebrow, "RALLY / VS
NAME" in Barlow Semi Condensed, and the `edge` line. The headline size shrinks
to fit the longest name.

Text is converted to SVG paths with `opentype.js` from the `@fontsource` WOFF
files and rasterized with `sharp`. Rendering text through sharp's own text input
was tried first and silently fell back to DejaVu Sans; paths remove any
dependency on the build machine's fonts.

### Page shape

Every comparison page has the same sections in the same order, and its side by
side table asks the same eight questions with Rally's column first, so two pages
can be read against each other. Class names are whole words that say what the
element is (`compare-answer`, `versus-table`, `footer-heading`).

## Invariants

- **One source per rival.** The Markdown file feeds the page, its card, the
  footer, the table, the comparison sitemap, `llms.txt`, and the build inputs. A footer link to a page the build
  never emits is a 404, so nothing else may list or count rivals. Guard: the
  site tests render the footer, table, sitemap and `llms.txt` and
  assert them against the loaded list.
- **A file's name is its slug.** `loadComparisons` throws when they differ, which
  fails the build.
- **The section headings are a fixed vocabulary.** `renderComparisonPage` throws
  on an unknown `##` heading or a missing one of the two. Guard: the Markdown
  test in `apps/site/test/site.test.ts`.
- **The footer's help@ link keeps `data-site-action="support-contact-footer"`.**
  It lives in `renderSiteFooter`, so the tracking test renders the landing page
  through `renderSiteChrome` before it looks for ids. Guard: `tags every tracked
  landing link`.
- **Each page's date is true.** `updated` and the sitemap `lastmod` say when the
  claims were last checked against the rival's public pages. Bump both only after
  re-checking. No automated guard.
- **Claims about a rival are checkable.** The pages no longer list sources, so
  whoever edits a rival fact checks it against that rival's public pages first.
  Biased framing is fine; a wrong fact is not. Rally claims stay to what the
  landing page and support pages say. No automated guard; reviewed by hand.

## Boundary

The module owns the comparison pages, their social cards, the landing page's
comparison section, and the footer on those pages. The Trust Center pages
use this footer through the same marker; their own styling is `trust.css`,
which loads after `landing.css`. It does not own the
home page's social card (`scripts/generate-brand-assets.py`), or the
access-copy headline, which [`private-access.md`](private-access.md) owns.
What the pages report to PostHog is in
[`landing-page-tracking.md`](landing-page-tracking.md).

## Failure modes and limits

- A marker typo, an unknown section, a missing field, or a slug that doesn't
  match its file name throws, so `vite build` and `vite dev` fail loudly.
- An `edge` too long for two lines at 34px is cut with an ellipsis on the card;
  the page itself shows it in full.
- Cards are about 185 KB each, well under the 5 MB X and 8 MB Facebook limits.
  `_headers` caches them for a day, like the home card, so an edited card can
  take a day to refresh in unfurl caches.
- The comparison pages classify as `landing` in site telemetry because
  `sitePageForPath` has no `compare` class. Their page views carry their own
  `$pathname`; the landing dashboards filter on `/` and are unaffected.
- Rival facts go stale. Each page shows its date so a reader, human or model,
  can judge freshness.

## Testing

`pnpm --filter @rally/site exec vitest run test/site.test.ts` renders the footer
and the table and asserts their links, renders a fixture Markdown page and
asserts its table, cards, quotes, meta tags and validation errors, draws a card and checks it is a 1200x630 opaque PNG, and runs the
tracking check over the rendered landing page. Layout and the cards are verified
visually: build, serve `dist` with `vite preview`, screenshot the landing
section, the footer, and one rival page at 1440px and 390px, and open
`dist/compare/*/social.png`.

## Changelog

### 2026-10-01: Drop the closing buttons, render quotes anywhere

**What changed:** The "See Rally pricing" and "Compare Rally with other tools"
buttons no longer close each comparison page. A blockquote in the short answer
now has its own quiet style, and anything after the "Side by side" table
renders instead of being dropped.

**Why:** The team asked for the buttons to go; the header and footer already
link to pricing and the other comparisons. The ChatGPT page put a blockquote
under its short answer, which rendered with browser defaults, and the table
section silently discarded anything after the table.

**Considered and rejected:** Moving every blockquote into the closing aside, as
"Where Rally wins" does. The ChatGPT quote belongs next to the short answer it
qualifies, not at the foot of a later section.

**Consequences:** A comparison page ends at its last section; a call to action
there needs a new decision, not a restored constant. A blockquote's place in the
Markdown is where it renders, except in "Where Rally wins", where it is still
the aside.

Shipped in #1054.

### 2026-10-01: The header's links become a shared marker

**What changed:** The landing page and the comparison pages each carried their
own copy of the header nav. Both now hold `<!-- rally:site-nav -->`, rendered by
`renderSiteNav`, which adds a Blog link between Compare and Download for Mac.
The plugin that renders comparison pages is renamed `rally-markdown-pages` and
also renders the blog, described in [`site-blog.md`](site-blog.md).

**Why:** Adding the Blog link meant editing two copies of the nav, and the copies
already differed only in whether links started with `/`. One renderer keeps them
identical.

**Considered and rejected:** Keeping per-page navs with relative `#features`
links on the landing page. The absolute `/#features` form works on every page,
and on the landing page it scrolls without a reload.

**Consequences:** A header link goes in `renderSiteNav`, never in a page. The
Trust Center pages still write their own nav, so a link added there is separate.

Shipped in #1052.

### 2026-10-01: Trust Center pages take the landing's chrome

**What changed:** The eight `/trust/` pages drop their own light header,
footer and Arial stylesheet. They load `landing.css`, use the landing's
`site-header`, and replace their hand-written `legal-footer` with
`<!-- rally:site-footer -->`. `information.css` becomes `trust.css`, holding
only the Trust Center's layouts, written against the landing's tokens.

**Why:** The Trust Center looked like a different company's site from the
landing page it links from. Sharing the stylesheet and the footer marker keeps
them from drifting again, and the eight copies of the footer link list, which
had already diverged in order and tagline, collapse into `trustPages`.

**Considered and rejected:** Restyling `information.css` in place and keeping
each page's own header and footer. That matches the look today but leaves nine
copies of the chrome to drift, which is how the footers diverged.

**Consequences:** `trust.css` assumes `landing.css` loads first for fonts,
tokens, the header, buttons and `.eyebrow`. A trust page that links only
`trust.css` renders unstyled. A change to the landing's header, footer or tokens
now also changes the Trust Center.

Shipped in #1046.

### 2026-10-01: Comparison pages keep only the table and Rally's case, and the hub is removed

**What changed:** Each rival page drops "Where <name> shines", "Which one
should you pick?", "Questions" and "Sources", along with the `FAQPage` JSON-LD
and the verdict and sources styles. The pricing and comparison buttons that sat
under the verdicts now follow "Where Rally wins". Instinct, Notion AI and
Microsoft Teams are removed, leaving six rivals, and the comparison table loses
its dated caption. The `/compare/` hub page, its social card, and the
count, names and item-list markers only it used are removed; every link that
pointed at it now points at the landing table, and `_redirects` sends
`/compare/` and the three removed rival pages there too.

**Why:** The team wanted shorter pages that make Rally's case and stop there,
and the hub only repeated the landing page's table.

**Considered and rejected:** Keeping the sections in the Markdown and hiding
them in the renderer: copy nobody shows still has to be kept true.

**Consequences:** The pages no longer carry the FAQ markup or source links
that the first entry gave as the reason AI search engines cite them. If that
traffic matters later, bring back `## Questions` first. The `/compare/`
redirects match exact paths, so they must stay exact or they would swallow
the remaining rival pages.

Shipped in #1045.

### 2026-10-01: Comparison pages, their social cards, and a column footer are added

**What changed:** The landing page gains a "Compared to" section after
Technology, the site gains `/compare/` and nine "Rally vs X" pages rendered at
build time from Markdown, each with its own drawn social card, and the landing
footer becomes columns: Compared to, Trust Center, and Help.

**Why:** Buyers ask AI search engines "Rally vs Slack" and similar before they
visit, and comparison pages with a direct answer, a table, an FAQ and sources
are what those engines cite. Links to these pages get shared in Slack and on X,
where a generic card hides what the page is about. The old footer was one flat
row of links with no room for nine more.

**Considered and rejected:** Hand-written HTML per page, which was the first
version: copy edits meant editing markup, and nine copies of the same layout
drift. Committed PNG cards made by a script: they go stale the first time
someone edits a page's `edge`. Sharp's built-in text rendering for the cards:
it fell back to the system font without an error. A copied footer in every
page: eleven copies of the rival list would drift.

**Consequences:** A new rival is one Markdown file. A new footer link goes in `renderSiteFooter`, never in a page.
The site build now depends on `sharp`'s native binary and on the `@fontsource`
packages for the card fonts. `opentype.js` is pinned to exactly 1.3.4: npm's 1.3.5 is a
mistaken publish of 2.0.0, deprecated by its maintainers. `sharp` follows the
0.35.2 the workspace already locks, so the site adds no second copy.

Shipped in #1040.
